# liblc3

Google's LC3 (Low Complexity Communication Codec, ETSI TS 103 634) encoder and
decoder, the second codec of the musegadgets BLE protocol: 16 kHz mono, 10 ms
frames, 40 bytes a frame (32 kb/s) by default. One copy serves both SDKs: the
ESP32 component [`esp32/components/liblc3`](../../esp32/components/liblc3)
compiles these sources with the options below for the ESP32 BLE gadgets,
and the Zephyr gadgets (in a later change) use the same ones.

| | |
|---|---|
| Upstream | https://github.com/google/liblc3, the library Zephyr ships as its `liblc3` module |
| Version | commit `8e1e722cda8dbdcc4b3cb9ba559d11c236c33d07` (2026-09-09) |
| License | Apache-2.0, Copyright 2022 Google LLC. See [`LICENSE`](LICENSE). The trimming is by Meta Platforms, Inc. and affiliates under the same license. |

## What's upstream and what's ours

The sources are an optimized build of upstream; the changes are listed below,
and each changed file says so in its header. The bitstream stays standard LC3.

| File | From |
|---|---|
| `include/lc3.h` | upstream, unmodified |
| `include/lc3_private.h` | upstream, modified: state sized for builds without LTPF |
| `src/lc3.c` | upstream, modified: frame durations and sample rates outside `LC3_DT_MASK` / `LC3_SR_MASK` are rejected so their code drops out; LTPF and TNS can be compiled out; encode and decode reject an unknown PCM format (upstream indexes its function tables with it) |
| `src/bits.c` | upstream, modified: the bit reader doesn't shift by 32 on an overrun frame (a frame that reads past its end is refused either way) |
| `src/common.h` | upstream, modified: the build can define `LC3_HOT`, empty for sanitizer builds |
| `src/fastmath.h` | upstream, modified: `lc3_exp2f()` adds the exponent in unsigned arithmetic (the same bits, no signed overflow) |
| `src/tns.c`, `src/tns.h`, `src/tables.h` | upstream, modified: optional TNS and LTPF trimming |
| `src/tables.c`, `src/ltpf.c` | upstream, regenerated for 16 and 24 kHz / 10 ms by `tools/trim_tables.py`: other configurations' table entries are NULL so the linker drops their tables |
| `src/tables_mask.h` | Meta, generated by `tools/trim_tables.py`: the masks of the configurations the tables carry, `lc3.c`'s defaults, and a `_Static_assert` that stops a build whose masks let another in (its tables are NULL) |
| `tools/trim_tables.py` | Meta: regenerates the three files from upstream for a set of rates (with `--rates 16k` it reproduces the 16 kHz-only trim exactly) |
| the other `src/` files | upstream, unmodified |
| `LICENSE` | upstream, unmodified |
| `README.md` | Meta |

## Build options

Both SDKs build the same configuration:

- `LC3_DT_MASK=8`, `LC3_SR_MASK=6`: 10 ms frames at 16 and 24 kHz (the
  rates the SDKs use, and the defaults: the tables carry no others);
  other durations and rates are rejected at setup, and a mask that lets one
  in doesn't compile.
- `LC3_ENC_LTPF=0`, `LC3_DEC_LTPF=0`: no long-term postfilter. These size the
  encoder and decoder state, so every user of `lc3.h` needs them. The encoder
  signals LTPF off in every frame, so any standard LC3 decoder plays the
  stream.
- `LC3_PLUS=0`, `LC3_PLUS_HR=0`: no LC3plus modes.
- `LC3_ENC_TNS` exists but stays at its default (TNS on).

The ESP32 adds `-ffast-math`: the decoder's output then differs from exact
float by up to ~600 LSB (about -50 dBFS RMS), which leaves its SNR as it
was. A firmware that only encodes (the Zephyr gadget) gets no decoder: the
linker drops it.

## Numbers

16 kHz speech at 32 kb/s:

| | Upstream | This build |
|---|---|---|
| PESQ-WB | 4.13 | 4.15 (4.17 on Cortex-M33) |
| Encoder code + data, ESP32-S3 | 102 KB | 35 KB |
| Encoder, Xtensa with FPU (ESP32 in QEMU; the S3 is similar) | 23.6 MIPS | 7.5 MIPS |
| Encoder, RV32IMC without FPU (ESP32-C3 in QEMU; the C6 and C5 have no FPU either) | 180 MIPS | 85 MIPS |
| Encoder, Cortex-M33 with FPU (emulator, `-O2`) | 105 KB flash | 35 KB flash, 1.9 KB static RAM, 2.5 KB stack, 7.1 MIPS |

LC3 is floating point, so on the ESP32-C6 and C5 it takes about half the CPU
while recording; SBC, the default, needs 2 MIPS there.

## Updating

Take the new upstream release's `include/` and `src/`, apply the changes
listed above again, regenerate `tables.c`, `ltpf.c` and `tables_mask.h` with
`python3 tools/trim_tables.py <upstream>/src --rates 16k,24k` (the rates
the SDKs' `LC3_SR_MASK` lets through), and keep the modification notes in
the other files' headers. With `LC3_ENC_LTPF=1 LC3_DEC_LTPF=1` the trimmed
copy must stay bit-exact with upstream at each rate. Then run `python3
xplat/tests/run_tests.py` and `python3 xplat/tests/run_tests.py --sanitize`
from the repository root (CI: `.github/workflows/xplat.yml`).
